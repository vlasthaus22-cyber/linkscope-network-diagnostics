# LinkScope — проверка сетевых соединений

Локальная HTML-панель для проверки доступности устройства, потерь пакетов, задержки, пропускной способности и просмотра текущих сетевых соединений. Схема сети хранится в браузере на этом компьютере.

## Запуск

1. Установите Python 3.9 или новее.
2. В PowerShell откройте эту папку и запустите `.\start.ps1`, либо выполните:

   ```powershell
   python server.py
   ```

3. Откройте `http://127.0.0.1:8765`.
4. Выберите источник и цель на схеме, способ проверки (Python, PowerShell или CMD), режим порта и порог скорости.

## Проверка проекта

Запустите встроенные тесты Python без сторонних зависимостей:

```powershell
python -m unittest discover -s tests -v
```

## Проверка скорости без iperf3

В LinkScope встроен TCP-замер: на источнике он не требует установки `iperf3` или дополнительных библиотек. При запуске `server.py` TCP-приёмник автоматически начинает слушать порт 8766 на этом компьютере. На целевом устройстве достаточно запустить LinkScope; отдельный `receiver.ps1` для обычного теста не нужен.

Если на целевом компьютере нельзя запускать LinkScope, `receiver.ps1` остаётся запасным вариантом:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\receiver.ps1
```

Встроенный приёмник слушает порт 8766; разрешите входящие TCP-подключения к этому порту в firewall. В автоматическом режиме LinkScope ищет приёмник на стандартных портах; нестандартный порт можно выбрать вручную. Автопоиск SSH перебирает стандартные порты 22, 2222 и 2200; нестандартный задаётся вручную. Для измерения до удалённого устройства LinkScope должен быть запущен на цели. Для обратного направления запустите LinkScope на другом конце.

Чтобы выполнять замер от другого устройства, добавьте его на схему, выберите его в поле «От устройства» и заполните SSH-пользователя и SSH-порт. На удалённом источнике требуется включённый OpenSSH Server и Windows PowerShell; локально должен быть доступен `ssh.exe`. Для беспарольного подключения используйте ключ SSH или `ssh-agent`. Сначала подтвердите host key устройства обычным SSH-подключением. По SSH панель запускает замер с удалённого Windows-источника до выбранной цели; на цели должен быть запущен приёмник.

Устройства можно добавлять кнопкой «Устройство», перетаскивать по схеме, редактировать и удалять. В окне добавления доступен автопоиск IPv4-устройств по локальной подсети: она определяется по адресу компьютера, маска может потребовать ручной правки в формате CIDR. Поиск проверяет ping, типовые порты 22, 80, 443, 445, 3389, 8080 и 8766, а также локальный ARP-кеш; доступны подсети до 1024 адресов. Устройства с включённым firewall могут не отвечать на ping и TCP-проверки, но могут отображаться в ARP-кеше. Выберите найденный адрес, заполните карточку и нажмите «Сохранить». В карточке также можно отметить наличие логина и пароля; логин сохраняется в схеме браузера, а пароль — только в `sessionStorage` до закрытия вкладки. SSH-проверка использует ключ или `ssh-agent`, парольная SSH-аутентификация пока не поддерживается. Начальная схема содержит примерные узлы и IP-адреса: замените их своими через «Изменить выбранное». В выборе «От устройства» укажите источник, в «До устройства» — цель; кнопка «Связь» добавляет эту пару на схему. На целевом устройстве достаточно запустить LinkScope, чтобы включить встроенный TCP-приёмник.

Режим iperf3 оставлен как дополнительная опция, если он уже установлен на обоих концах. Для ping доступны режимы Python (системные команды `ping` и `netstat`), PowerShell (`Test-Connection`, `Get-NetTCPConnection`, `Get-NetUDPEndpoint`) и Windows CMD (`ping`, `netstat`). Интерфейс адаптеров и согласованная скорость линка читаются через `Get-NetAdapter` на Windows.

В блоке соединений отображаются удалённые IP-адреса, удалённые и локальные порты, TCP-состояния и процесс-владелец сокета. Список обновляется кнопкой и относится к компьютеру, на котором запущен агент. Для другого устройства нужно запустить LinkScope на нём. UDP не устанавливает постоянный сеанс: система обычно показывает только локальный порт процесса, без адреса удалённого устройства.

## О границах программной диагностики

Обычный сетевой адаптер не может программно проверить электрическую целостность каждой жилы кабеля. Приложение проверяет сетевую доступность и фактический поток данных, а также показывает согласованную скорость локального порта. Для диагностики обрыва/перепутанных пар нужен кабельный тестер или поддерживаемая самим адаптером аппаратная диагностика. Низкая измеренная скорость может быть вызвана кабелем, портом, нагрузкой, Wi-Fi, настройками или firewall.

Панель по умолчанию слушает только `127.0.0.1` и доступна с этого компьютера. Не публикуйте локальный сервер в сеть без настройки аутентификации и правил доступа.
